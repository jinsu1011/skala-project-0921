# Decision Log

형식: **결정 / 근거 / 검토한 대안**

## 설계 단계 (2026-09-21)

**D1. 기술 선정은 Human 기반(2안)으로 하고 에이전트는 사후 검증만 한다.**
- 근거: 에이전트가 고르면 최신 자료 편중과 비교 계층 불일치 위험이 있다. 사람이 선택하되 `selection_validator`가 원문 근거로 검증해 추적성을 확보한다.
- 대안: (1안) 선정 에이전트. 실행마다 선정 결과가 달라져 설계서와 보고서가 어긋날 위험이 있고, 에이전트가 하나 늘어난다.

**D2. SW는 TurboQuant, HW는 ITME로 한다.**
- 근거: 가중 기준표(공정성 35, 근거 25, 산업 25, 최신 15)에서 진영별 최고점이다(4.60 / 4.50). 두 기술 모두 모델을 바꾸지 않는 서빙 계층 기술이다.
- 대안: MLA(사전학습이 필요해 제외 조건 ③), InfiniGen(2.95), CXL-PNM(2.90).

**D3. TRL은 기술 조사 Agent가 맡고, 별도 노드 `trl_assessor`로 분리해 Fan-out에 넣는다.**
- 근거: 원 논문을 이미 읽는 에이전트라 성숙도 근거를 보기에 자연스럽다. 노드를 분리하면 Judge가 TRL만 선택적으로 재실행할 수 있다. `tech_research`에 두면 재실행 때 Fan-out 전체가 다시 돈다.
- 대안: 독립 TRL 에이전트(불필요한 에이전트 증가), `tech_research` 내부 처리(선택적 재실행 불가).

**D4. Judge 에이전트를 추가한다(총 7개).**
- 근거: 중립성, 인용, 출처 다양성을 코드 수준 품질 게이트로 보장하고 Loop와 Branch의 근거를 만든다. 새 사실을 만들지 않으므로 역할이 겹치지 않는다.
- 대안: 평가 종합 에이전트에 통합(생성자와 검증자가 같아져 자기평가 편향 발생).

**D5. `document_loader`를 `index_builder`에 합친다.**
- 근거: 로드, 페이지 한도 확인, 청킹, 인덱싱이 한 번에 실행되는 결정적 단계라 분리해도 얻는 것이 없다. 그래프 높이도 줄어 가독성이 좋아진다.
- 대안: 팀 초안의 분리 구조. State 키 `document_manifest`는 그대로 두고 작성 노드만 바꾼다.

**D6. 보고서 검수(`final_check`)를 PDF 렌더링보다 먼저 한다.**
- 근거: 마크다운 단계에서 인용, 형식, 우열 표현을 고치는 편이 싸고, 불필요한 PDF 재생성을 피할 수 있다.
- 대안: 팀 초안(PDF → 검수 → 재작성).

**D7. `human_review`는 기본 실행에서 경고만 남기고 진행한다. `--interactive`일 때만 `interrupt`한다.**
- 근거: 채점자가 명령 한 줄로 재현할 수 있어야 한다.
- 대안: 항상 사람 입력을 기다림(자동 재현 불가).

**D8. 임베딩은 `BAAI/bge-m3`로 한다.**
- 근거: 자체 교차언어 평가(42문항)에서 Hit@1/3/5와 MRR이 모두 1위이고, SW·HW 균형도 가장 좋다. 1,024 토큰을 받아 청크 전체를 수용하고, MIT 라이선스이다.
- 대안: Qwen3-0.6B(팀 초안 가정. MRR 0.631, HW 0.493으로 편차 큼), e5-large(512 토큰 제한), MiniLM(128 토큰 제한).

**D9. 검색 구성은 3중 RRF(Dense KO + Dense EN + BM25 EN)에 bge-reranker-v2-m3를 붙인다.**
- 근거: MRR이 0.703(dense)에서 0.790(3중 RRF), 0.863(+rerank)으로 올랐다. 보고서 생성은 배치 작업이라 질의당 4.7초 지연을 수용한다.
- 대안: dense 단독, 2중 RRF(MRR 0.786), `--no-rerank` 옵션으로 제공.

**D10. Qwen3는 모델 카드의 기본 `query` 프롬프트로 비교한다.**
- 근거: 직접 만든 지시문(0.548)보다 성능이 좋아(0.631), 후보마다 최적 설정으로 비교하는 것이 공정하다.
- 대안: 직접 만든 지시문(불리한 조건).

**D11. 평가셋 영어 재작성은 질문만 보고 생성 모델이 만든다.**
- 근거: 정답 청크를 본 LLM이 재작성하면 누설로 BM25 점수가 0.816으로 부풀려진다. 런타임 `query_rewriter`와 같은 조건으로 측정해야 한다.
- 대안: QC 단계에서 재작성(폐기).

**D12. 청크는 900 토큰, 겹침 15%, 절 경계 우선으로 한다. 참고문헌은 제외하고 부록은 유지한다.**
- 근거: 팀 설계(800~1,000 토큰, 15%)를 따른다. 참고문헌 청크는 검색 잡음을 만든다. 부록에는 실험표가 많아 유지한다.
- 대안: 페이지 단위 청킹(절 정보 손실).

**D13. arXiv PDF는 커밋하지 않고 다운로드 스크립트만 둔다.**
- 근거: 재배포 라이선스가 불명확하다. `scripts/download_papers.py`가 페이지 수까지 검증한다.
- 대안: PDF 커밋.

**D14. Mermaid는 mermaid.js를 vendoring하고 헤드리스 Chrome으로 로컬 렌더링한다.**
- 근거: mermaid.ink 같은 외부 서비스로 다이어그램을 업로드하지 않는다. 오프라인에서도 재현할 수 있다.
- 대안: mermaid.ink API(외부 전송이라 정책상 차단됨), mermaid-cli(puppeteer Chrome을 추가로 다운로드해야 함).

**D15. 산출물 PDF는 SKALA 공식 docx 양식을 python-docx로 채우고 LibreOffice로 변환한다.**
- 근거: 제출 양식을 준수한다(사용자 요청). 맑은 고딕이 없는 환경에서는 PDF 변환 때만 Apple SD Gothic Neo로 대체한다.
- 대안: HTML → Chrome PDF(양식 미준수).

**D16. 팀 가설 4개와 초기 가설 4개를 H1~H4로 통합한다. "우위로 지목", "순위 비교" 표현은 "평가 방향이 엇갈림"으로 바꾼다.**
- 근거: 우열 판정 금지 원칙(Notion). 초기 H1·H2(배포 용이성, 무손실 용량)는 도메인 기준과 H4에 흡수했다.
- 대안: 가설 8개(보고서 분량 과다), 팀 원문 그대로(순위 비교는 우열 판정으로 읽힘).
